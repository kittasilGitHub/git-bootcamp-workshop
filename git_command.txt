// git command

ขั้นตอนการใช้งาน Git พื้นฐานสำหรับการทำงานจริง เรียงลำดับจากเริ่มสร้างโปรเจกต์ไปจนถึงส่งโค้ดขึ้นเซิร์ฟเวอร์ มีดังนี้ครับ
## 1. ขั้นเริ่มต้นโปรเจกต์ (ทำครั้งแรกครั้งเดียว)

* สร้าง Repository ใหม่: git init
(สร้างโฟลเดอร์ Git เพื่อเริ่มติดตามการเปลี่ยนแปลงในเครื่อง)
* เชื่อมโปรเจกต์กับระบบออนไลน์: git remote add origin <URL-ของ-GitHub>
(ระบุปลายทางว่าจะส่งโค้ดไปเก็บไว้ที่ไหนบน GitHub/GitLab)

## 2. ขั้นตอนการทำงานประจำวัน (วนลูปทำทุกครั้งที่แก้โค้ด)

   1. เช็กสถานะไฟล์: git status
   (ดูว่ามีไฟล์ไหนถูกแก้ไขหรือสร้างใหม่บ้าง)
   2. เลือกไฟล์ที่จะเตรียมบันทึก: git add <ชื่อไฟล์> หรือ git add .
   (คำสั่ง git add . หมายถึงเลือกไฟล์ที่แก้ไขทั้งหมดเพื่อเตรียมบันทึก)
   3. บันทึกประวัติการแก้ไข: git commit -m "ข้อความอธิบายการแก้ไข"
   (เป็นการเซฟสถานะโค้ดไว้ในเครื่องตัวเอง พร้อมเขียนโน้ตสั้นๆ ว่าแก้อะไรไป)
   4. อัปเดตโค้ดเพื่อนร่วมทีม (ถ้ามี): git pull origin <ชื่อ-branch>
   (ดึงโค้ดล่าสุดจากเซิร์ฟเวอร์ลงมาเครื่องตัวเองก่อน เพื่อป้องกันโค้ดตีกัน)
   5. ส่งโค้ดขึ้นเซิร์ฟเวอร์: git push origin <ชื่อ-branch>
   (ส่งข้อมูลที่ Commit ไว้ทั้งหมดขึ้นไปออนไลน์)

## 3. ตารางสรุปลำดับการพิมพ์คำสั่งที่ใช้บ่อยที่สุด
หากเปิดคอมมาทำงานในวันปกติ ลำดับการพิมพ์คำสั่งจะเป็นดังนี้:

| ลำดับ | คำสั่ง Git | หน้าที่ |
|---|---|---|
| 1 | git pull origin main | ดึงโค้ดล่าสุดของทีมมาอัปเดตในเครื่องก่อนเริ่มงาน |
| 2 | (เริ่มนั่งเขียนโค้ด/แก้ไขไฟล์ตามปกติ) | — |
| 3 | git status | ตรวจสอบความเรียบร้อยของไฟล์ที่แก้ |
| 4 | git add . | เตรียมไฟล์ทั้งหมดเข้าคิวรอส่ง |
| 5 | git commit -m "fix: bug login" | บันทึกประวัติพร้อมเขียนกำกับ |
| 6 | git push origin main | ส่งโค้ดขึ้นเซิร์ฟเวอร์ออนไลน์ |

หากต้องการทราบรายละเอียดเพิ่มเติม สามารถพิมพ์บอกได้เลยครับ:

* วิธีแยกกิ่งไปทำงาน (Git Branch)
* วิธีดูประวัติการบันทึกย้อนหลัง (Git Log)
* วิธีแก้ปัญหาโค้ดชนกัน (Conflict) เมื่อ Pull หรือ Push ไม่ผ่าน


การทำ Git Branch (การแยกกิ่ง) คือการแยกพื้นที่ทำงานออกมาจากโค้ดหลัก (ส่วนใหญ่คือสาย main หรือ master) เพื่อให้คุณสามารถทดลองฟีเจอร์ใหม่ๆ หรือแก้บั๊กได้โดยไม่กระทบกับโค้ดที่ใช้งานได้อยู่ครับ
ขั้นตอนและลำดับคำสั่งที่ใช้ในการจัดการ Branch มีดังนี้:
## 1. วิธีสร้างและสลับ Branch ทำงาน
หากต้องการเริ่มทำฟีเจอร์ใหม่ ให้ทำตามลำดับนี้:

* เช็ก Branch ปัจจุบัน: git branch
(ดูว่าตอนนี้เราอยู่ที่กิ่งไหน กิ่งที่มีเครื่องหมาย * คือกิ่งที่เราอยู่)
* สร้าง Branch ใหม่: git branch <ชื่อ-branch-ใหม่>
(เช่น git branch feature-login เพื่อสร้างกิ่งสำหรับทำระบบล็อกอิน)
* สลับไปทำงานที่ Branch นั้น: git checkout <ชื่อ-branch-ใหม่>
(หรือใช้คำสั่ง git switch <ชื่อ-branch-ใหม่> ก็ได้)
* ⚡ ทางลัด (สร้างและสลับทันที): git checkout -b <ชื่อ-branch-ใหม่>
(พิมพ์คำสั่งนี้คำสั่งเดียว จะได้ทั้งสร้างและย้ายเข้าไปทำงานในกิ่งนั้นทันที)

------------------------------
## 2. ขั้นตอนการทำงานและการส่งกิ่งขึ้นเซิร์ฟเวอร์
เมื่อสลับมาที่ Branch ใหม่แล้ว ให้แก้โค้ดตามปกติ จากนั้นทำตามลำดับนี้:

   1. บันทึกโค้ดในเครื่อง: ทำตามลำดับปกติคือ git add . แล้วตามด้วย git commit -m "ข้อความ"
   2. ส่ง Branch นี้ขึ้นออนไลน์ครั้งแรก: git push -u origin <ชื่อ-branch>
   (เพื่อให้บน GitHub/GitLab มี Branch นี้โผล่ขึ้นมาด้วย)

------------------------------
## 3. วิธีรวม Branch กลับเข้าโค้ดหลัก (Merge)
เมื่อทำฟีเจอร์เสร็จเรียบร้อยและต้องการนำโค้ดใน Branch ย่อยกลับมารวมกับกิ่งหลัก (main):

   1. สลับกลับไปที่กิ่งหลักก่อน: git checkout main
   2. ดึงโค้ดล่าสุดของกิ่งหลักลงมา (กันพลาด): git pull origin main
   3. สั่งรวมร่าง: git merge <ชื่อ-branch-ย่อย>
   (โค้ดจากกิ่งย่อยจะวิ่งเข้ามาที่กิ่ง main ในเครื่องของคุณ)
   4. อัปเดตขึ้นเซิร์ฟเวอร์: git push origin main

------------------------------
## 4. การลบ Branch ที่ใช้งานเสร็จแล้ว
เมื่อรวมโค้ดเรียบร้อยและไม่ได้ใช้กิ่งย่อยนั้นแล้ว ควรลบทิ้งเพื่อไม่ให้รก:

* ลบ Branch ในเครื่องตัวเอง: git branch -d <ชื่อ-branch>
* ลบ Branch บนเซิร์ฟเวอร์ออนไลน์: git push origin --delete <ชื่อ-branch>

คุณต้องการให้แนะนำวิธี สร้าง Pull Request (PR) บน GitHub เพื่อให้คนในทีมรีวิวก่อน Merge หรืออยากรู้วิธี จัดการปัญหาโค้ดชนกัน (Merge Conflict) เผื่อเกิดขึ้นระหว่างรวม Branch ดีครับ?
